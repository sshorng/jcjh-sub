# RDQ 需求規格：三角調功能

## 目前決定
- 需求規格已確認並保存；目前暫不開發，待使用者日後確認有實際需要時再執行。

## 一句話任務
在保留既有再調動與兩人調課的前提下，規劃三位教師整堂課循環交換的三角調流程。

## ✅ 已確認
- 使用者希望增加「三角調」，認為現有再調動與目標功能相近但仍有差異。（Ⅰ）
- 三角調是整堂課交換、屬於一調再調形成的三方關係，不是代課。（Ⅰ）
- 單一交換端點原本可能看似衝堂，但完成三方交換後的最終配置可能不衝堂，不能用逐筆中間狀態判定。（Ⅰ）
- 整堂課交換的基線是教師連同自己的班級／科目換到對方時段；網頁課表呈現交換後安排，紙本保留必要的原始端資料。（Ⅰ）
- 第一版納入三角圖與角色預覽、整組撤回／取消、三方通知與列印。（Ⅳ）
- 現有系統已有兩人調課、再調動與多段調代鏈解析，可作為底層基礎。（環境掃描）

## ❓ 假設（未確認，已採預設值，隨時可推翻）
- 三角調沿用既有調課的整堂課交換語意，透過一調再調形成三位教師與三堂課的閉環，不以代課或代課義務轉移表示。（預設）
- 送出前以三方交換完成後的最終課表驗證；中間步驟的暫時衝堂不直接否決，但最終配置不得有人同時負責兩堂課。（預設）
- 三位教師都同意且教學組核准後才整組生效；拒絕或衝堂時整組不生效。（預設）
- 新增三角調成組流程，以 `triangleId` 管理三條交換關係，不把三角調偽裝成三張互不相干的兩人調課單。（預設）
- 三角調的交換課堂須是有效一般課程；巡堂與真正空堂不作為交換課堂。（預設）
- 撤回採整組狀態異動，保留通知、列印與審計紀錄，不直接刪除單筆資料。（預設）

## ➕ 已採納（象限Ⅳ）
- 送出前顯示三角關係、三位教師角色，以及三堂課的交換前／交換後對應。（Ⅳ）
- 可用 `triangleId` 整組撤回／取消，避免留下部分生效的異動。（Ⅳ）
- 通知信、LINE 範本、行事曆與紙本單據完整列出三方關係。（Ⅳ）

## ❌ 排除項（明確不做）
- 不以代課申請或多次代課義務轉移模擬三角調。
- 第一版不做同一節課的 `A → B → C` 代課接力模型。
- 不以逐筆先核准的兩人調課結果，取代三方整體最終狀態驗證。
- 不自動把失敗的三角調拆成兩人調課。
- 第一版不納入待回覆期限與逾期自動失效。
- 不用「原課教師 → 實際授課教師」單向箭頭取代整堂課交換關係。

## 📋 一段式需求規格
請為 **建成國中線上課表系統** 規劃獨立的「三角調」流程，保留既有再調動與兩人調課行為不變。三角調是既有整堂課交換在一調再調後形成的三方閉環：三位教師各提供一堂有效原課，系統呈現三堂課的交換前／交換後關係，不把它當成代課或代課義務轉移。由發起人選定另外兩位教師與要交換的課堂，系統建立一個 **triangleId** 及三條交換關係，送出前以三角圖清楚呈現三位教師、三堂課與交換後結果，並以整組交換完成後的最終課表驗證衝堂；單一中間步驟看似衝堂，不得在尚未套用完整交換前直接否決。三位教師須完成同意，且教學組核准後整組生效；任一人拒絕、最終配置衝堂或驗證失敗時，三條交換關係均不得生效。系統需支援以 **triangleId** 整組撤回／取消，保留歷史與審計資訊，並讓通知信、LINE 範本、行事曆與紙本單據完整表達三方交換關係。巡堂與真正空堂不作為交換課堂，既有特殊課程規則沿用；底層可重用現有調課／再調動解析、衝堂檢查、核准與列印能力，但不可將三角調拆成互不相干的兩人申請或代課申請。

## ✔ 驗收條件
- [ ] 能建立三位不同教師、三堂原課的整堂課交換預覽，並正確顯示三方角色、交換前後課堂與結果。
- [ ] 對「中間步驟看似衝堂、完整三角交換後不衝堂」案例，系統依最終配置通過整組模擬；真正的最終衝堂仍整組拒絕。
- [ ] 三方未全部同意或教學組未核准前，任何一條 leg 都不進入有效課表；拒絕與驗證失敗不產生半組結果。
- [ ] 可用 `triangleId` 查詢、撤回或取消整組資料，且歷史、通知與列印不遺失三方關係。
- [ ] 既有兩人調課、再調動、多段調代鏈、代課流程與 `class=` 公開課表回歸測試不受影響。
